# Security Threat Model

Threats enumerated per brief section 10. For each: the concrete mitigation in `contracts/agentverdict.py`, and the negative test in `tests/direct/` that exercises it (file names refer to the Stage 1/2/3 test suite built in this session).

| Threat | Mitigation | Test |
|---|---|---|
| Prompt injection in evidence URLs/content | Evidence text is wrapped with an explicit "DATA, not instructions" framing before being placed in any LLM prompt (feature 35); the contract never executes or reinterprets instructions found in fetched content; malicious payloads are treated as evidence content only, never as calls to contract methods | `test_evidence.py::test_prompt_injection_payload_is_inert`, `test_api_delivery.py::test_malicious_evidence_content_does_not_change_decision_path` |
| Malformed JSON from LLM | Defensive parsing (`_parse_llm_json`): strips wrapping text, fixes trailing commas, validates every expected key exists and has the right type before use; any failure raises `ERROR_LLM`-prefixed `UserError`, never a bare exception | `test_api_delivery.py::test_malformed_llm_json_raises_llm_error` |
| Broken redirects / huge pages | `gl.nondet.web.get` calls are wrapped with a byte-length cap read from the response (`_MAX_EVIDENCE_BYTES = 4000` chars post-decode) before anything is placed in a prompt; redirect-following and TLS behavior are delegated to GenVM's web module (not independently re-implemented) — recorded as unverified scope in `GENLAYER_CAPABILITY_MATRIX.md` | `test_evidence.py::test_oversized_evidence_is_truncated_not_rejected_outright` |
| SSRF-like targets | `submit_evidence` only accepts `http://`/`https://` URL schemes and rejects `file://`, `ftp://`, bare IPs in RFC1918 ranges (10.x, 172.16-31.x, 192.168.x), and `localhost`/`127.0.0.1`/`0.0.0.0` hostnames at submission time, before any fetch is ever attempted | `test_evidence.py::test_rejects_private_and_local_urls`, `test_evidence.py::test_rejects_non_http_scheme` |
| Stale / replayed evidence | De-duplication by `content_hash` per `agreement_id` (replay rejected); `Evidence Freshness Monitor` (feature 13) records `submitted_at` and the evaluation module's fetch-time status so UI/read methods can show evidence age — this contract does not attempt to prove content authenticity (hashes are integrity commitments, not authenticity proofs, per spec invariant #6) | `test_evidence.py::test_rejects_duplicate_content_hash_same_agreement` |
| Source substitution | Not independently detectable on-chain without re-fetching (which the validator does); flagged as a residual risk — see "Open risks" below | — (documented gap) |
| Compromised agent wallet | No private-key-level mitigation is possible from the contract; standard scoped-delegation revocation (`revoke_delegation`) lets a counterparty cut off a compromised delegate's authority immediately; `AgentPassport.revoked` lets admin freeze a known-compromised identity from registering new agreements | `test_access_control.py::test_revoked_passport_cannot_submit_evidence` |
| Forged delegation | `delegate_scope` is callable only by the parent for itself (`gl.message.sender_address` must equal the `parent` argument — you cannot delegate on someone else's behalf); `accept_delegation` requires the child to be `gl.message.sender_address` | `test_access_control.py::test_cannot_delegate_on_behalf_of_another_address` |
| Replayed evidence / evaluation requests | `request_evaluation` requires state `EVIDENCE_OPEN`/`REEVALUATING`; a second call before a new evidence/rework cycle is rejected by the state guard, not by hoping the caller behaves | `test_state_machine.py::test_request_evaluation_requires_evidence_open_state` |
| Reentrancy / double settlement | `record_settlement` flips `SettlementInstruction.status` to `EXECUTED` **before** attempting any outbound transfer (idempotency-first ordering); `authorize_settlement` rejects a second authorization while one is already `AUTHORIZED`/`EXECUTED` | `test_settlement.py::test_double_settlement_rejected`, `test_settlement.py::test_authorize_settlement_idempotent` |
| Privilege escalation | Every admin-only method (`register_module`, `resolve_challenge`, `set_settlement_native_transfer_enabled`) checks `gl.message.sender_address == self.admin` deterministically; every party-only method checks against the stored `Agreement.creator`/`counterparty` fields, never against caller-supplied claims | `test_access_control.py::test_only_admin_can_register_module`, `test_access_control.py::test_only_admin_can_resolve_challenge` |
| Griefing through appeals | One open `Challenge` per agreement at a time (guard in `challenge_verdict`); challenge grounds string is length-capped (`_MAX_GROUNDS_LEN`); no bond is charged in V1 because real GEN custody is disabled by default (see `PROTOCOL_ARCHITECTURE.md` section 5) — **this is a known, stated gap**: without a bond, a party can challenge every verdict for free, which is a real griefing vector if this contract is deployed as-is with high-value agreements. Recorded as an open risk below, not silently mitigated. |
| Sybil farms | `AgentPassport` registration is free and permissionless by design (spec: "wallet-linked verifiable history", not KYC); Sybil resistance (feature 40) is **not implemented** in Stage 1-3 — `reputation_score` only accrues from finalized verdicts tied to real agreements with real counterparties, which raises the cost of farming reputation (each fake reputation event requires a full agreement lifecycle with a cooperating counterparty) but does not prevent two colluding wallets from doing so. Recorded as an open P1/P2 gap. |
| Data leaks | No private file uploads exist anywhere in this contract; `submit_evidence` only ever stores a URL + hash + MIME type string, never raw content; this directly enforces spec section 0's "no secrets or private uploaded files on-chain" | `test_evidence.py::test_evidence_packet_never_stores_raw_content` |
| Unavailable web sources | Classified `ERROR_EXTERNAL`/`ERROR_TRANSIENT` (see `EQUIVALENCE_MATRIX.md`); `request_evaluation` catches the classified error and persists `EVALUATION_ERROR` state rather than leaving the agreement stuck in `EVALUATING` with no record | `test_api_delivery.py::test_unreachable_api_yields_insufficient_evidence_or_evaluation_error` |
| Validator disagreement | Not resolvable inside a single transaction's Python logic — this is GenVM consensus's job once deployed; this contract's responsibility, which it meets, is to make the comparison function deterministic and well-defined so a real disagreement reflects a genuine semantic difference, not a bug in the comparison itself | `test_api_delivery.py::test_validator_disagrees_on_different_decision` |
| Chain reorg / finality ambiguity | The contract never treats `PROVISIONAL` as final in any read method (`get_verdict` always returns the `state` field alongside `decision`); `finalize_verdict` is the only transition into `FINALIZED`, gated on the challenge window closing with no open challenge — the frontend (not yet built) is required to surface GenLayer's own underlying consensus/finality status separately from this application-level state, per spec section 4.2's "a proposed consensus result is not protocol-final until network finality and application challenge requirements are both met" | documented; frontend-side enforcement deferred to Stage 4 |
| Browser wallet spoofing | Out of scope for the contract (frontend/wallet-integration concern); deferred to Stage 4 frontend work, not yet built | deferred |

## Open risks (stated plainly, not smoothed over)

1. **No challenge bond.** Because real GEN custody is disabled by default (section 5 of `PROTOCOL_ARCHITECTURE.md`), `challenge_verdict` cannot require a forfeitable bond without contradicting the "no fake escrow" invariant. A production deployment that re-enables `settlement_native_transfer_enabled` should also add a bonded-challenge path before handling meaningful value — not present in this build.
2. **Admin centralization for module registry and challenge resolution.** A single admin key currently decides module registration and challenge outcomes. This is explicitly flagged in `PROTOCOL_ARCHITECTURE.md` section 6 and is the honest reason features 12 (Precedent), 17 (Negotiation), and 20 (Collusion Detection) are not implemented — they would need a real decentralized-jury design this session did not have the scope to build and verify.
3. **Source substitution between leader and validator fetch.** If a target server serves different content based on request timing/IP/headers, the validator's independent re-fetch is the only defense, and it is a weak one against a sophisticated adversary. No stronger defense (e.g., signed evidence commitments with a reveal window — feature 36) is implemented yet; it is designed in the spec but not built this session.
4. **Sybil-resistant reputation (feature 40) not implemented.** See table row above.
5. **genvm-lint / Studio runtime version mismatch.** A clean lint pass does not prove Studio will load the contract (see `GENLAYER_CAPABILITY_MATRIX.md` section 2). No live Studio deployment was performed this session to close this gap.
